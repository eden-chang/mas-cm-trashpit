# 6.3 - Vercel 웹 배포 가이드

`web` 폴더의 Vite + React 웹앱을 Vercel로 발행하는 단계별 가이드입니다.

---

## 사전 준비

- [GitHub](https://github.com) / [GitLab](https://gitlab.com) / [Bitbucket](https://bitbucket.org)에 프로젝트가 푸시되어 있어야 합니다.
- [Vercel](https://vercel.com) 계정 (GitHub 등으로 가입 가능).

---

## 1단계: Vercel 가입 및 프로젝트 가져오기

1. **https://vercel.com** 접속 후 **Sign Up** 또는 **Log In**.
2. **Add New…** → **Project** 선택.
3. **Import Git Repository**에서 사용 중인 저장소(예: GitHub)를 연결한 뒤, `trashpit`(또는 해당 저장소)를 선택하고 **Import** 클릭.

---

## 2단계: 빌드 설정 (Root Directory 필수)

이 저장소는 **루트가 Python/봇**이고, 웹앱은 **`web`** 폴더에 있으므로 **Root Directory**를 반드시 지정해야 합니다.

1. **Configure Project** 화면에서:
   - **Root Directory**: **Edit** 클릭 → `web` 입력 후 **Continue**.
2. **Framework Preset**: **Vite**가 자동 감지되면 그대로 두고, 아니면 **Vite** 선택.
3. **Build and Output Settings** (필요 시 **Override** 체크):
   - **Build Command**: `npm run build` (기본값 유지)
   - **Output Directory**: `dist` (Vite 기본값)
   - **Install Command**: `npm install` (기본값 유지)

4. **Deploy** 클릭.

---

## 3단계: 환경 변수 — VITE_API_BASE_URL (API 연동 시 필수)

Vercel에 올린 웹은 **정적 사이트**라서 같은 주소에는 `/api`가 없습니다. 캐릭터/가방을 불러오려면 **API 서버 주소**를 환경 변수로 알려줘야 합니다.

### 3-1. 어디에 등록하나요?

**등록 위치:** Vercel 대시보드에서 **지금 웹(프론트엔드)을 배포한 그 프로젝트**입니다.  
(API를 배포한 프로젝트가 아니라, **Vite 웹페이지를 배포한 프로젝트**에 넣습니다.)

1. **https://vercel.com** 접속 후 로그인.
2. 상단/좌측에서 **웹(trashpit 등)을 배포한 프로젝트** 클릭.
3. 상단 탭에서 **Settings** 클릭.
4. 왼쪽 메뉴에서 **Environment Variables** 클릭.

여기서 변수를 추가하면 됩니다.

### 3-2. 무엇을 넣나요?

| 항목 | 입력값 |
|------|--------|
| **Key (이름)** | `VITE_API_BASE_URL` (오타 없이 정확히) |
| **Value (값)** | API 서버의 **전체 주소** (끝에 `/` 없음) |

**값 예시:**

- API를 **다른 Vercel 프로젝트**로 배포했다면  
  → 그 프로젝트의 배포 URL  
  예: `https://mas-cm-trashpit-api.vercel.app`
- **Railway, Render, 본인 서버** 등에 API를 올렸다면  
  → 그 서버의 주소  
  예: `https://trashpit-api.railway.app`, `https://api.trashpit.site`

**주의:**

- `https://` 또는 `http://` 를 **반드시** 포함합니다.
- 끝에 슬래시(`/`)를 붙이지 않습니다.  
  (예: `https://api.example.com` ✅ / `https://api.example.com/` ❌)
- 웹 코드는 이 주소 뒤에 `/api/characters`, `/api/character/이름` 등을 붙여 요청합니다.  
  따라서 **값은 “서버 주소만”** 넣으면 됩니다.

### 3-3. 등록 절차 (화면 기준)

1. **Environment Variables** 화면에서 **Add** 또는 **Add New** 클릭.
2. **Key** 란에 `VITE_API_BASE_URL` 입력.
3. **Value** 란에 위에서 정한 API 서버 주소 입력.
4. **Environment**는 **Production**, **Preview**, **Development** 중 필요한 것 선택 (보통 **Production**만 체크해도 됨).
5. **Save** 클릭.

### 3-4. 반영 시점

- Vite는 빌드할 때 `VITE_` 로 시작하는 변수만 코드에 넣습니다.
- 변수를 **추가하거나 수정한 뒤에는** 반드시 **한 번 더 배포(Redeploy)** 해야 합니다.
  - **Deployments** 탭 → 최신 배포 오른쪽 **⋯** → **Redeploy** 로 다시 배포하면 됩니다.

### API를 아직 배포하지 않은 경우

- **캐릭터/가방 API**(Flask 등)를 **먼저** Railway, Render, 다른 Vercel 프로젝트 등에 배포한 뒤, 그 URL을 받아야 합니다.
- 그 URL을 위에서 설명한 **Value**에 넣으면 됩니다.

---

## 4단계: 배포 확인

1. 배포가 끝나면 **Visit** 링크로 사이트 접속.
2. SPA 라우팅(예: `/bag`, `/free` 등)으로 직접 이동해도 404가 나지 않고 `index.html`이 서빙되는지 확인.
   - `web/vercel.json`에 `rewrites`가 설정되어 있어 이 동작이 가능합니다.

---

## 5단계: 커스텀 도메인 (선택)

1. Vercel 대시보드에서 프로젝트 선택 → **Settings** → **Domains**.
2. **Add**로 도메인 입력 후, DNS에 안내된 CNAME/ A 레코드 설정.

---

## CLI로 배포하는 방법

터미널에서 직접 배포하려면:

```bash
# Vercel CLI 설치 (최초 1회)
npm i -g vercel

# web 폴더로 이동 후 로그인 및 배포
cd web
vercel
```

최초 실행 시 로그인과 프로젝트 연결을 묻습니다. **Set up and deploy?** 에서 **Y** 선택 후, Root Directory 질문이 나오면 **current directory**를 선택하면 됩니다.

이후 배포만 반복할 때:

```bash
cd web
vercel --prod
```

`--prod`는 프로덕션 도메인에 배포합니다.

---

## 트러블슈팅

| 증상 | 확인 사항 |
|------|-----------|
| 빌드 실패 (Module not found 등) | Root Directory가 `web`으로 설정되었는지 확인. |
| 404 on refresh / 직접 URL 접속 | `web/vercel.json`의 `rewrites`가 있는지, Root가 `web`인지 확인. |
| API 호출 실패 | 프로덕션 API URL을 환경 변수(`VITE_*`)로 설정했는지, CORS가 허용되는지 확인. |
