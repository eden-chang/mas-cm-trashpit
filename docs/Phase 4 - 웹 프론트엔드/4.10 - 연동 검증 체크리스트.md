# 구글 시트 ↔ 웹사이트 연동 검증 체크리스트

> Phase 4 완료 전 필수 검증 항목

## 검증 환경 준비

### 필수 서버 실행

```bash
# 터미널 1: API 서버
cd trashpit
python api/app.py

# 터미널 2: 웹 개발 서버
cd trashpit/web
npm run dev
```

### 자동 테스트 실행

```bash
# 읽기 전용 테스트 (권장)
python scripts/run_integration_tests.py

# 쓰기 포함 테스트 (주의!)
TEST_CHARACTER=테스트캐릭터 python scripts/run_integration_tests.py --write
```

## 2. 데이터 흐름 테스트

### 흐름 A: 시트 → API → 웹

```
[구글 시트] → [Flask API] → [React 웹]
```

| 단계 | 확인 방법 | 기대 결과 | 결과 |
|------|-----------|-----------|------|
| 1. 캐릭터 목록 | GET `/api/characters` | 캐릭터 배열 반환 | ☐ |
| 2. 캐릭터 상세 | GET `/api/character/{name}` | 전체 정보 반환 | ☐ |
| 3. 가방 조회 | GET `/api/bag/{name}` | 용량/아이템 반환 | ☐ |
| 4. 주변 조회 | GET `/api/nearby/{name}` | 주변 아이템 반환 | ☐ |
| 5. 웹 UI 표시 | 캐릭터 선택 후 UI 확인 | 데이터 정확히 표시 | ☐ |

### 흐름 B: 웹 → API → 시트

```
[React 웹] → [Flask API] → [구글 시트]
```

| 단계 | 확인 방법 | 기대 결과 | 결과 |
|------|-----------|-----------|------|
| 1. 가방 저장 | POST `/api/bag/{name}` | 성공 응답 + 시트 반영 | ☐ |
| 2. 아이템 이동 | POST `/api/nearby/{name}/move` | 성공 + 가방/주변 갱신 | ☐ |
| 3. 시트 확인 | 구글 시트에서 직접 확인 | 데이터 변경됨 | ☐ |
| 4. 캐시 무효화 | 즉시 재조회 | 최신 데이터 반환 | ☐ |

## 4. 에러 처리 테스트

| 상황 | API 응답 | 웹 UI 반응 | 결과 |
|------|----------|-----------|------|
| 존재하지 않는 캐릭터 | 404 | 에러 메시지 표시 | ☐ |

| 부족한 수량 이동 | 400 | 에러 알림 | ☐ |
| API 서버 다운 | 연결 실패 | 네트워크 에러 표시 | ☐ |

## 5. 동시성 테스트 (선택)

> ⚠️ 현재는 Last-write-wins 정책

| 시나리오 | 테스트 방법 | 예상 결과 | 결과 |
|----------|------------|-----------|------|
| 두 브라우저 동시 수정 | 탭 2개에서 같은 캐릭터 수정 | 마지막 저장이 반영 | ☐ |
| 봇 + 웹 동시 수정 | 봇 명령 중 웹에서 저장 | 나중 작업이 반영 | ☐ |

## 6. Supabase–웹–봇 연결성 테스트 (선택)

> 데이터 소스: **Supabase** 한 곳. 봇과 API가 동일 DB를 사용하므로, 봇 명령 반영 후 API/웹에서 동일 데이터가 보여야 함.

### 자동 테스트 (봇 → Supabase 반영 검증)

```bash
# 전제: ENABLE_BOT_SUPABASE_TESTS=true, TEST_CHARACTER, TEST_MASTODON_ID, TEST_ITEM 설정
# (상세 전제는 docs/Phase 6 - 테스트 및 배포/6.1 - 테스트 시나리오.md 참고)
python scripts/run_integration_tests.py --bot
# 또는
ENABLE_BOT_SUPABASE_TESTS=true TEST_CHARACTER=... TEST_MASTODON_ID=... TEST_ITEM=... python -m pytest tests/test_bot_supabase_connection.py -v
```

| 명령어 | 봇에서 하는 일 (DB 변경) | API/웹로 검증하는 방법 | 결과 |
|--------|--------------------------|------------------------|------|
| **획득** `[획득/아이템명]` | 해당 캐릭터의 주변/여유공간에 아이템 추가 | `GET /api/character/{name}` 또는 `/api/nearby/{name}` 에 해당 아이템 존재 | ☐ |
| **버리기** `[버리기/아이템명]` | 주변/여유/가방에서 아이템 제거 | 같은 엔드포인트에서 해당 아이템 없음 또는 수량 감소 | ☐ |
| **사용** `[사용/아이템명]` | 아이템 1개 차감, 스탯 변경 | `GET /api/character/{name}` 에서 수량·스탯 반영 | ☐ |
| **양도(아이템)** `[양도/아이템/받는사람]` | 발신 인벤 감소, 수신 주변/여유 증가 | 발신·수신 둘 다 API로 조회해 일치 여부 확인 | ☐ |
| **양도(포인트)** `[양도/n포인트/받는사람]` | 발신/수신 `points` 증감 | `GET /api/character/{name}` 의 포인트 값 확인 | ☐ |
| **지급** `[지급/캐릭터/아이템]` (운영진 전용) | 수혜자 인벤에 아이템 추가 | 수혜자 API 조회 시 해당 아이템 존재 | ☐ |

### 수동 확인 (봇 실행 후 웹)

> 봇 실행: `python bot/main.py`

| 시나리오 | 테스트 방법 | 확인 사항 | 결과 |
|----------|------------|-----------|------|
| 아이템 획득 | 마스토돈에서 `[획득/테스트아이템]` | Supabase 반영 후, 웹 새로고침 시 주변에 아이템 표시 | ☐ |
| 웹 조회 | 봇 획득/버리기/사용/양도 후 웹 Refresh | API/웹에 동일 데이터 표시 | ☐ |
| 캐시 지연 | 봇 수정 직후 웹 조회 | 봇은 API 캐시를 무효화하지 않으므로, TTL(예: 30초) 이내 옛날 데이터 가능 | ☐ |
