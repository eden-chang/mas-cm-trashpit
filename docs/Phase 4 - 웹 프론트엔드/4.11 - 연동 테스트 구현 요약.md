## 테스트 실행 방법

### 1. 빠른 API 테스트

```bash
# API 서버 실행 (별도 터미널)
python api/app.py

# API 엔드포인트 테스트
python scripts/test_api_endpoints.py
python scripts/test_api_endpoints.py --character 캐릭터명
```

### 2. 통합 테스트

```bash
# 읽기 전용 테스트 (권장)
python scripts/run_integration_tests.py

# 특정 캐릭터로 테스트
python scripts/run_integration_tests.py --character 테스트캐릭터

# 쓰기 테스트 포함
python scripts/run_integration_tests.py --write
```

### 3. pytest 직접 실행

```bash
# 읽기 테스트만
pytest tests/test_integration.py -v

# 쓰기 테스트 (환경변수 필요)
TEST_CHARACTER=테스트캐릭터 ENABLE_WRITE_TESTS=true pytest tests/test_write_operations.py -v

# 캐시 테스트
pytest tests/test_cache.py -v
```

## 아키텍처 요약

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  React 웹       │────▶│  Flask API      │────▶│  Google Sheets  │
│  (localhost:    │     │  (localhost:    │     │  (원본 데이터)   │
│   5173)         │     │   5000)         │     │                 │
└─────────────────┘     └─────────────────┘     └─────────────────┘
        │                       │
        │   Vite Proxy          │   gspread + 캐시
        │   /api → :5000        │   TTL: 30초 (캐릭터)
        │                       │   TTL: 300초 (아이템)
```

### 데이터 흐름

1. **조회 흐름**: 웹 → API → 캐시/시트 → API → 웹
2. **저장 흐름**: 웹 → API → 시트 → 캐시 무효화 → 웹

### 캐시 무효화

- `update_bag_items()` → `invalidate_character_cache(name)`
- `update_nearby_items()` → `invalidate_character_cache(name)`
- `update_misc_items()` → `invalidate_character_cache(name)`
- `update_bag_and_nearby_items()` → `invalidate_character_cache(name)`

## 알려진 제한사항

### 1. 동시성

- **현재**: Last-write-wins (마지막 쓰기가 이김)
- **영향**: 봇과 웹이 동시에 같은 캐릭터 수정 시 데이터 충돌 가능
- **권장**: Phase 5에서 낙관적 락 또는 버전 관리 검토

### 2. 캐시 지연

- **현재**: 봇이 수정해도 API 캐시는 최대 30초간 이전 데이터
- **영향**: 웹에서 즉시 최신 데이터 미표시
- **권장**: 수동 Refresh 버튼 또는 봇→API 캐시 무효화 요청

### 3. 실시간 동기화

- **현재**: 없음 (수동 Refresh 필요)
- **권장**: Phase 5에서 WebSocket 도입 검토
